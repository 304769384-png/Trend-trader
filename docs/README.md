## 〇、版本迭代约定

**每次功能更新或缺陷修复后，版本号必须递增，不允许沿用旧版本号交付：**

- **对外版本（页面左上角徽标 + sw.js 缓存键）**：`vN` → 每次更新 +1，当前 **v41**，保证 Service Worker 能拉取新壳、旧缓存自动失效；**对外只展示这一个版本号**

## 〇·〇·一、v40 更新摘要（2026-10-01）

**对外版本 v40**（应用侧迭代，**评分逻辑完全不变**）：

1. **宽度抓取升级为「两个时点」**：`14:45–15:00` 抓 **盘中预估**（`pre=1`）→ 你在收盘前 15 分钟就能看到当日灯与仓位建议、**来得及在收盘前动手**；`15:25` 之后抓 **收盘定格**（`pre=0`）并**覆盖**当日预估值，保证入库序列与回测同口径。
2. **阶段化节流**：抓取不再只用「6 小时」节流，改为「6 小时 **或** 阶段推进」——同一阶段内重复打开不重复请求，阶段推进（14:45→15:25）时自动补抓一次。
3. **界面透明标注**：宽度行显示该条是「**盘中14:45预估值**」还是「**收盘定格**」，配合已有的「样本 N/20 日 · 最新日期」一眼可辨真伪。
4. **安全写入**：定格值（`pre=0`）**总是覆盖**盘中预估值；盘中预估值（`pre=1`）**仅在当日无记录时写入**，不会污染已成形的定格序列。节假日 14:45 抓到的仍是上一交易日定格值，不会误标为预估（按「标签是否等于本机今日」判定）。
5. **缓存键 `quant-app-v39 → v40`**；两盏灯结果键 `v8_regime_lights_v4` 不变，新增 `v8_regime_adv_phase`（记录上次抓取阶段）。
6. **文档同步**：README / `评分说明.md` / 部署指南全部更新到 v40。

## 〇·〇·二、v39 修复摘要（2026-10-01）

**对外版本 v39**（应用侧修复 + 数据重建，**评分逻辑完全不变**）：

1. **修复「周末/节假日打开 App，宽度不更新」**（手机端实测痛点：点了分析仍显示旧日期）：旧逻辑 `fetchLiveBreadth()` 在傍晚分支要求「指数最新交易日 === 今天」，非交易日（周末/节假日）直接 `return null` → 只要当天休市就永远抓不到、宽度停在旧值。现改为**统一以「指数最新交易日」为标签**：盘后已收盘→记今日；周末/节假日/凌晨→记最近一个已收盘交易日。这正是 2026-10-01（假期）手机端刷不出 2026-09-30 数据的原因。
2. **宽度写入改为「仅在缺该日时才写」**：既补漏（用户漏开的交易日），又避免指数 K 线滞后时把今日误标到昨日。
3. **宽度种子重建至 2026-09-30**：`regime_breadth.json` 改用 `market_data/live_930`（5538 只、含沪深京、至 09-30）重建近 60 交易日；与新浪当日口径校验一致（09-30 双边均为 46.1%）。**重建后的真实值：宽度20日均 = 43.1%（09-02~09-30）→ 灯2 亮；中证1000 距MA20 = -3.42% → 灯1 亮 → 两灯全亮 → 建议空仓。**（此前 v38 的种子停在 09-18，导致误显示 47.4%/灭，已纠正。）
4. **缓存键 `quant-app-v38 → v39`**；两盏灯结果键 `v8_regime_lights_v4` 不变。
5. **文档同步**：README / `评分说明.md` / 部署指南全部更新到 v39。

> 已知限制（诚实说明）：宽度序列只能「逐日累积」＋静态种子；App 无法回溯抓取**历史**每日宽度（新浪快照只给当日）。因此**长期不打开仍会形成缺口**，种子随版本更新。建议收盘后每天打开一次。

### v5.4（v38）变更摘要（2026-09-30）

**对外版本 v38**：应用侧与文档同步迭代（**评分逻辑完全不变**，仍为 v36 的回调结构定档口径）：

1. **两盏灯升级为「非对称分级降仓」并联动仓位卡**：旧版只在两灯全亮时给一句提示、仓位卡照常按上限给仓（用户反馈「两盏灯形同虚设」）。本版按实测把灯控变成**暴露系数**并直接压进仓位建议 ——
   - ① **两灯全亮 → 空仓**（×0）
   - ② **宽度单灯 < 42%（深弱）→ 空仓**（×0，即便中证1000 尚稳）
   - ③ **宽度单灯 42–44%（偏弱）→ 半仓**（×0.5）
   - ④ **中证1000 单弱（宽度 ≥44%）→ 不降仓**（×1；实证为超跌反弹区，越深越反弹：近4年 中证1000<-8% 后20日仍 +3.11%，砍掉反而拖累年化）
   - 依据：`backtest-v15/regime_dereisk.py`（thr70·Top8·cap20·含费·2014-10~2026-09，决策用昨日 regime）。现行两灯空仓 → 非对称分级：**近4年 33.9%/11.6%/1.65 → 34.4%/11.7%/1.71**；**全史 20.6%/38.4%/1.15 → 20.8%/38.8%/1.18**；前半/后半分段同向改善（非过拟合）。
2. **仓位卡直接显示「降仓后」结果**：单只/总仓按暴露系数缩放，并附「灯控×N（未降仓 X%）」对照；切换单只上限档位时同步按系数重算。旧版显示的是未降仓原值，用户会误以为灯不生效。
3. **宽度20日均「算没算」透明化**：灯2 行显式标注 **样本 N/20 日 + 最新数据日期 + 收盘定格**，一眼可验证 20 日均是否真的算出（不足 8 日则显示「未算出」）。
4. **导出 CSV 同步灯控**：元信息新增「小盘熊市两盏灯」行（亮灯数 / 中证1000距MA20 / 宽度20日均含样本天数与最新日期 / 分级规则），仓位建议含**灯控暴露系数**与「未降仓」原值对照。
5. **缓存与配置文件口径统一**：`sw.js` 缓存键 `quant-app-v37 → v38`；两盏灯结果键 `v8_regime_lights_v3 → v8_regime_lights_v4`；宽度序列 `v8_regime_adv_v1`（120 条）、市场过滤 `v8_mkt_filter_idx_v1`（同日缓存）、弱市开关 `v8_mkt_alert_on` 不变。
6. **文档同步**：本 README、`评分说明.md`、`docs/腾讯云部署指南.html` 全部更新到 v38 / 交付 v5.4，并补充「非对称分级降仓」说明。

## 一、这是什么

一个**纯前端、零后端**的量化助手，装到 iPhone 桌面后即可像原生 App 一样使用。核心能力：

- **十日线回踩选股评分**：对自选股票池回测近 60 日行情，按「十日线回踩」战法综合打分（0–100 分），结果自动显示股票名称（仅输入代码也会自动获取）。
- **ETF 动量轮动**：实时扫描 44 只行业 ETF，按 20 日动量选出 Top 3 等权持仓。
- **截图识别代码**：直接上传/拍照/粘贴同花顺选股截图，自动识别 6 位股票代码填入输入框。

## 二、快速开始

### 2.1 部署到静态服务器

这是纯静态应用，**无需构建**，任意静态托管（腾讯云开发 CloudBase / GitHub Pages / Nginx 等）均可直接部署。

```bash
# 本地预览（任意静态服务器即可）
cd quant-app
python3 -m http.server 8080   # 浏览器打开 http://localhost:8080/
```

部署到腾讯云开发静态托管：将 `quant-app` 目录内全部文件上传到静态托管根目录即可。若部署后界面仍是旧版，点页面左上角 `↻v41` 徽标强制刷新（会清缓存并注销旧 Service Worker）。

### 2.2 安装到 iPhone（PWA）

1. 用 **Safari** 打开部署好的 URL（必须 HTTPS 或 localhost）
2. 点底部「分享」按钮 → **「添加到主屏幕」**
3. 桌面出现黑金图标，点击即全屏独立运行

> 添加前请保持网络连接，Service Worker 会缓存应用壳，之后可离线打开。

## 三、功能模块

### 🎯 选股（选股评分）

**输入股票池**，三种方式：

1. **手动输入**：文本框每行一只，支持"代码 + 名称"，可用换行/逗号/空格分隔
2. **快捷样本**：`小样本` / `实战池` 一键填充演示数据，`清空` 重置
3. **截图识别**：点击「识别截图」卡片——拍照、相册、拖拽或 Ctrl+V 粘贴同花顺截图，自动识别 6 位代码，去重后「填入输入框」

**评分战法（十日线回踩）**，准入条件：

- 近 20 日出现过涨停
- MA10 > MA20（多头排列）
- 当日**缩量**阴线回踩
- 收盘价位于 MA10 附近（1.0 – 1.05 倍），且高于 MA20

满足条件后按 **6 项因子**打分（六因子桶分校准评分：官方七因子桶分 × 去 S2 等比放大权重，满分约 100.2，无状态权重、无风控乘数），再叠加 **S9/R9 扣分与 limit_vr 加分**（2026-09-15 定档；2026-09-19 在六因子上做 9 处桶分校准，详见 `评分说明.md`）：

| 因子 | 官方满分 | 初版权重 | 含义（校准桶分） |
|------|---------|--------|------|
| S1 回踩幅度 | 14.5 | 17.2 | 回踩 1.02–1.04 区间最高分；1.01–1.02 校准 6.4→2.0 |
| S3 回踩天数 | 20.0 | 23.7 | pd=3 最强信号 20 分；pd 4/6/13/19 校准 |
| S4 均线斜率 | 9.6 | 11.4 | 斜率 >0.07 最高 9.6 分 |
| S5 涨停次数 | 11.6 | 13.7 | 近 20 日 2 次涨停最高 11.6 分 |
| S6 涨停放量比 | 18.6 | 22.0 | 5.5–6.0 最高 18.6 分；<1.0 校准 6.5→2.0、≥6.0 校准 3.6→10.0 |
| S8 gap | 10.3 | 12.2 | 0.02–0.03 最高 10.3 分；4-5%/5-6% 校准 |

> 已剔除因子：S2 量比（滚动方向稳定性 0.308<0.7）。S5 涨停次数**保留参与评分**（主评分口径；同期备选方案曾剔除，按用户裁决保留）。

**状态展示**：应用自动缓存近 20 日市场情绪，判定 5 种市场状态（强势上攻/题材活跃/震荡整固/弱势调整/极端波动）**仅作推荐榜展示参考，不参与评分**——评分与市场状态解耦，逻辑稳定可复现。

**风险标注（仅展示、不参与评分）**：跌停（≤-9.5%）/ 大跌（≤-5%）/ ST 仅打标签；**风控乘数（×0.4/×0.7/×0.9）已于 2026-09-19 取消**——26 年 D1 审计实锤超跌反弹为正收益，乘数惩罚过度。

**推荐门槛**：评分 **≥ 70** 才推荐（推荐区），**≥ 75** 优选，**≥ 80** 精选。依据组合层双回测（2026-09-19，`reports/bucket-calib.html`）：Top8 · 阈值 70 · 上限 20%，全史年化 +15.54%（vs 旧版 +7.0%）、近 5 年 +44.95%（vs +30.10%），收益与回撤双优。

结果区展示每只股票的**综合分、各分项、触及条件、风险提示**，并给出评分分布（≥80 / 70–80 / 60–70 / <60），支持 **导出 CSV**。

### 🌀 ETF（ETF 轮动）

- 样本池 **44 只行业 ETF**（含宽基、行业、主题、黄金等）
- 策略：当日价须站上 MA20 与 MA60 → 按 **20 日动量**降序取 **Top 3** → **等权持仓**
- 候选不足时空仓；市场状态仅作展示参考，不强制门控
- 展示入选标的、动量、权重，以及历史调仓回测记录

## 三·五、每日操作 SOP · 市场宽度（收盘定格）与 CSV 导出

### 3.5.1 为什么宽度要「本地每日收盘后刷新」

灯2（小盘熊市「两盏灯」之一）用的**市场宽度 = 上涨家数占比**。这个值**盘中随时在变**——09:30 与 14:30 可以完全不同；而回测用的日频宽度取的是**每日收盘定格值**。因此 App 只在**收盘后或次日凌晨**打开时才抓取并写入当日宽度，**盘中一律不写**，保证序列里每一条都与回测同口径。

| 打开 App 的时间 | App 行为 |
|---|---|
| 09:30–15:00（盘中） | 不抓取、不写入任何宽度；灯2 用历史序列（静态种子 + 已累积）算最近 20 日均值 |
| **15:25–24:00（盘后）** | **打开即自动抓取当日收盘宽度并本地缓存**（6 小时内只尝试一次，无需点击）；若中证1000 日K尚未更新到今日则本次跳过 |
| 00:00–08:30（次日凌晨） | 补录：按「上一交易日」日期写入（用于当天收盘后没来得及打开的情况） |
| 周末 / 节假日 | 指数未更新或全市场无有效涨跌 → 自动跳过、不写入，不污染序列 |

### 3.5.2 每日 3 步（收盘后）

1. **15:25 之后用手机打开一次 App，停在首页即可** —— 约 1.5 秒后自动后台抓取宽度（无需任何点击）。
2. 点「开始评分」跑当日选股，**灯2 / 两盏灯自动用最新收盘宽度**。
3. 需要留档就点结果区「导出 CSV」。

> ⚠ 请勿在盘中反复打开指望它更新宽度——**盘中不会写**。若某天忘记打开，次日凌晨打开会自动补录上一交易日。
> 无需再手工导出/上传 `regime_breadth.json`（现已自动抓取）；该文件仅作**历史种子**保留，保证清缓存/换机后立即有完整 20 日序列。

### 3.5.3 灯1 / 灯2 定义与「非对称分级降仓」（联动仓位卡，不改变选股结果）

- **灯1** = 中证1000(000852) 收盘距 MA20 **< -2%**（腾讯指数日K，1 次请求）
- **灯2** = 市场宽度(上涨家数占比) MA20 **< 44%**（**< 42% 记为「深弱」**；新浪「沪深A股」快照二分定位上涨占比，约 8 次请求；失败回退静态种子）

**分级降仓（v38 实测定档，作为暴露系数直接压进仓位建议）**：

| 状态 | 灯控暴露 | 仓位建议 |
|---|---|---|
| 两灯全亮 | ×0 | **空仓** |
| 宽度单灯 < 42%（深弱，中证1000 尚稳） | ×0 | **空仓** |
| 宽度单灯 42–44%（偏弱） | ×0.5 | **半仓** |
| 中证1000 单弱（宽度 ≥44%） | ×1 | **不降仓**（超跌反弹区，越深越反弹） |

> 实证（`regime_dereisk.py`，thr70·Top8·cap20·含费）：宽度单灯深弱近4年后20日 **-3.46%**（真风险）；中证1000 单弱近4年 中证1000<-8% 后20日仍 **+3.11%**（反弹区）—— 两者方向相反，故**非对称**处理，只对宽度弱降仓。**仅影响仓位建议，本次推荐结果不受影响。**

### 3.5.4 导出 CSV 说明

结果区点「导出 CSV」→ 生成 `jayce-score-YYYY-MM-DD.csv`（UTF-8 带 BOM，中文不乱码），共 3 段：① **元信息**（成本口径 / 评分时刻 / 市场过滤 / 仓位建议含灯控暴露系数 / **小盘熊市两盏灯**：亮灯数·中证1000距MA20·宽度20日均含样本天数与最新日期）；② **合格池明细**（总分与各因子）；③ **未入选名单**。

- **代码列为文本格式** `="002345"`，Excel 双击打开保留前导零（不会变成 2345）。
- 若用「数据 → 从文本 / CSV 导入」，请把代码列类型设为**文本**再导入。
- **首次导出**会弹一次说明提示（仅首次），结果区按钮下方也有常驻说明条。

### 3.5.5 本地缓存与配置文件

| 键 / 文件 | 用途 | 说明 |
|---|---|---|
| `v8_regime_adv_v1` | 宽度序列 | 保留最近 120 条，去重后按日期升序 |
| `v8_regime_lights_v4` | 两盏灯结果 | 同日缓存 |
| `v8_mkt_filter_idx_v1` | 市场过滤信号 | 同日缓存 |
| `v8_mkt_alert_on` | 弱市提醒开关 | 用户偏好 |
| `regime_breadth.json` | 历史种子 | 随包发布（近 60 交易日），清缓存/换机后立即补齐 20 日序列 |
| SW 缓存键 `quant-app-v41` | 应用壳 | 只缓存壳；行情/宽度接口（腾讯/新浪）**永不缓存**，网络优先、离线回退 |

## 四、技术架构

### 4.1 文件结构

```
quant-app/
├── index.html        # 应用本体：全部界面 + 样式 + 逻辑（单文件）
├── manifest.json     # PWA 清单：名称 / 图标 / 全屏 / 竖屏
├── sw.js             # Service Worker：离线缓存（缓存键 quant-app-v40）
├── regime_breadth.json # 市场宽度历史种子（近 60 交易日，清缓存/换机后立即补齐 20 日序列）
├── README.md         # 本说明文档
├── 评分说明.md        # 评分模型完整说明（六因子桶分校准 + S9/R9 扣分 + 加分项，半数取偶舍入，无风控乘数）
├── docs/             # 部署指南
│   └── 腾讯云部署指南.html
├── reports/          # 设计说明与回测报告（应用内评分规则页可直接打开）
│   ├── bucket-calib.html          # 桶分校准设计说明（9 处校准审计依据）
│   └── 桶分校准与双回测.html       # 全时段/近3年双口径对比回测报告
└── icons/            # 应用实际引用的桌面图标（icon-180/192/512/512-maskable）
```

> 上传部署时**必须整体上传、保持目录结构**（`reports/`、`icons/`、`docs/` 相对路径不可缺失）。

### 4.2 数据流

```
同花顺截图 ─→ OCR(Tesseract.js) ─→ 股票代码 ─→ 输入框
                                                   │
腾讯行情接口(web.ifzq.gtimg.cn) ─→ 近60日K线 ─→ 十日线回踩评分 ─→ 结果 ─→ 导出 CSV

市场宽度(灯2): 收盘后打开 App → 新浪沪深A股快照(二分定位上涨占比) → 本地缓存(收盘定格)
             └ 失败/非交易时段 → 回退同源 regime_breadth.json 历史种子
```

### 4.3 关键设计

- **行情走腾讯接口**：`web.ifzq.gtimg.cn` 前复权日 K 线，8 秒超时防挂起
- **SW 策略**：网络优先，失败回退缓存壳；行情域名（`gtimg.cn`/`sina`）**永不缓存**保证实时
- **OCR**：Tesseract.js（`chi_sim` + `eng`），首次需下载约 15MB 引擎，之后离线可用；`isValidStockCode()` 校验前缀过滤噪音（沪 `600/601/603/605/688`、深 `000/001/002/003/300/301`、北交所、ETF 等）
- **设计**：纯黑深空 + 香槟金，红涨绿跌，iOS 原生动效，适配刘海安全区

### 4.4 UI 布局

两个主 Tab 由**底部 Dock** 统一导航：`选股评分` / `ETF 轮动`。底部主按钮随 Tab 切换（选股页为「开始评分」，ETF 页为「获取信号」）。

## 五、常见问题

**Q1：首次识别提示"请选择图片"？**
已修复。应用现在先用 `FileReader` 把图片读成 dataURL 再交给异步 OCR，避免首次下载引擎期间文件引用失效。

**Q2：识别只出来一部分代码？**
请确保截图**显示代码列**（如 `603726`）。识别用 `isValidStockCode` 校验前缀，`000` 开头的深市代码也能正常识别。

**Q3：如何离线使用？**
首次在线打开后，`sw.js` 已缓存应用壳。之后断网也能打开，但行情类实时数据需联网。

**Q4：评分结果如何导出？**
评分结果区点击「导出 CSV」，生成 `jayce-score-YYYY-MM-DD.csv` 下载。股票代码以文本格式导出（`="002345"`），在 Excel 中打开保留前导零，不会变成 2345。首次导出会弹一次说明提示（文件分段 / 导入注意），之后不再打扰；按钮下方也有常驻说明条。详细字段见 §3.5.4。

**Q7：市场宽度（灯2）为什么打开 App 也不更新？**
因为宽度**只在收盘定格**：App 仅在**收盘后（15:25–24:00）或次日凌晨（00:00–08:30）**打开时抓取并写入当日宽度，**盘中（09:30–15:00）不抓、不写**，以保证与回测同口径。正确做法是**收盘后（15:25 之后）打开一次 App 停在首页**即可。详见 §3.5。

**Q8：清缓存或换手机后，宽度会不会要重新累积？**
不会。包内 `regime_breadth.json` 提供近 60 交易日历史种子，App 启动即读取并与本地缓存按日期合并，**清缓存/换机后立即拥有完整 20 日序列**，无需等待累积。

**Q6：点击「开始评分」后界面整体上移、顶部被挡？**
已修复（v30）。根治方案为三层防御：① `.app` 改为 `position:fixed` 并以 `--app-top` 跟随 `visualViewport.offsetTop`，从结构上杜绝 iOS 为露出输入框而偷偷滚动的推挤；② 键盘弹出时贴合可视区高度、收起立即还原满屏；③ 交互后用 rAF 循环（~700ms）只把「文档级」滚动归零，**不动结果区内部滚动**。同时对 `html/body/.pane` 设置 `overscroll-behavior:none`。

**Q5：Tesseract 引擎加载失败？**
OCR 引擎走 CDN，需要联网下载一次。若失败请检查网络，或在有网环境先打开选股页完成首次加载。
